# 工程学术插画

将导航、定位、多源感知与工程应用中的概念转成清晰、严谨、高可信度的学术汇报图形。**任何时候**都遵循“**以克制 2.5D 工程插画/矢量情景为统一骨架，在关键技术锚点有机嵌入真实实物与定量科学图**”的原则——既完整保留 2.5D 工程图的美观度、空间一体感与流畅动线，又赋予核心器件与结论真实的工程质感与数据支撑，绝不退化成几张矩形照片的生硬拼贴。

## 核心原则（任何时候均须遵守）

### 1. 视觉骨架与真实素材融合原则（保留 2.5D 美感，杜绝生硬拼贴）

无论场景大小或汇报场合，构建示意图始终严格遵循以下原则：

1. **统一视觉骨架先行**：先确立干净克制的 2.5D 工程插画或统一透视的矢量情景底图（白底、浅灰建筑/结构、柔和连贯的数据流与空间关系），保证整体构图美观、视角统一、动线流畅；**绝不为了放实物而把整张图拆成几张扁平的矩形照片拼贴**。
2. **核心锚点真实素材有机嵌入（优先级顺序）**：
   - **第一优先（本人/团队一手素材）**：优先使用用户提供的实物照、平台界面、目标 PPT 已有素材，以及作者/团队已发表论文中的核心实测图件；
   - **第二优先（权威公开实物与科学图）**：其次选用公开授权（Public Domain / CC-BY）的真实卫星透明抠图、真实传感器/载具硬件实物、权威地球/环境实测场，以及配色与底图统一的定量科学图（如 `nav-sciplot` 误差曲线）；
   - **融入方式**：实物优先采用**无底透明抠图原位替换**（如真实卫星直接接管信号波束）、**克制圆形/微阴影放大视窗 + 细虚线引出**（如硬件模组、实测载具特写），以及**同色系细边框浮卡 + 虚线锚点**（如定量误差图挂接在融合平台上方），做到与 2.5D 主画风浑然一体。
3. **文字与数据严谨性**：**严禁在图内标题、图例或标注中出现“模拟示例”“示意数据”“Demo”“Placeholder”等破坏专业感的字样**；如系公开演示样例，来源与说明仅写在图外文档注脚中。

详细检索、抠图去杂边、放大视窗融入、论文单子图无损裁切及 PPTX 装配方法见 [混合示意与实物拼装指南](references/hybrid-schematic-guide.md)。

### 2. 四项构图与文字硬核查

1. **空间尺度对齐**：主题涉及“全球 / 广域 / 区域 / 局部 / 室内”时，底图与对象必须匹配对应尺度（如“全球”须呈现真实地球、全球倾角轨道与跨洲站网，不得用局部草地或单点近景敷衍）。
2. **实物锚点对齐**：嵌入的实物照与科研图件必须精准绑定**核心科学问题或核心研究工作**（如多源融合绑定传感器实物与误差对比图、全球观测绑定地球与大气/电离层分布图），不为了凑图放次要外围设备。
3. **文字减法与直观释义**：
   - 有目标 PPT 时，先通读整页文本，**页面正文已写清的内容绝不在图内重复**；
   - 图内只保留高信息密度短标签，字号以实际放映尺寸清晰可读为准；
   - 汇报人本人或团队成果图在图内用**一句简短中文直白解释图意**（例如说明颜色对比或物理含义），不强行标注“引自某文献/某机构”式尾注（除非用户明确要求注明出处）。
4. **终端与成果具象化**：反映用户端指标或应用效果（如厘米级定位、PNT 服务）时，优先在场景中放置**轻量化具象终端/载具（如车辆、无人机、船舶等）+ 极简短标签**，既避免只放干瘪文字，也避免在情景图中堆砌过多复杂误差曲线。

### 3. 主次与辅助关系视觉语法

当图中包含“核心主线”与“辅助/支撑工作”时，必须从构图和配色上让人一眼分清主次，避免画成权重相等的并列模块：

- **主线工作**：沿用目标 PPT 高饱和主题色（如深红）、占据更大视觉面积、使用实线主干箭头直连核心平台与最终输出；
- **辅助/支撑工作**：采用低饱和冷色线框卡或浅色从属模块，以虚线或汇聚箭头直接指向并汇入主线核心模块；
- **关系标签贴线放置**：说明辅助关系的短词（如“遮挡辅助 · 抑制发散”）**直接压在对应的物理/逻辑连线上**，不悬空漂移在连线外侧。

## 按用途选择模式

| 模式 | 用途与组织方式 | 案例目录 |
| --- | --- | --- |
| 混合情景示意图（默认优先） | 以真实实物照、权威科学图/本人论文核心图与克制矢量情景框架混排，表达空间关系、机理或主次支撑 | [hybrid-schematic-guide](references/hybrid-schematic-guide.md) |
| 单体场景插画 | 放入页面局部的一张独立插画，解释一个场景、现象或概念；也可是一张并列场景图 | [single-scenes](assets/single-scenes/) |
| 局部组合示意图 | 放入页面局部，由独立图件、文字和技术连线组成，说明局部机理或流程 | [local-diagrams](assets/local-diagrams/) |
| 全页系统示意图 | 占据页面主要内容区，组织多个场景、模块或空间层次，解释整体系统、技术路线或部署方案 | [system-overviews](assets/system-overviews/) |

按使用范围和信息组织方式分类，不按对象数量分类。空间关系图和系统架构图不必强行画成顺序流程。

选择内置案例参考时读取 [案例选择与维护](references/asset-guide.md)，按需列出对应分类目录中的现有图片并选择相关案例，不依赖固定编号或数量。案例仅作构图与表达参考，不是可编辑源文件，也不是技术事实依据。

## 输入与构图

- **已有 `.pptx` 文件**：优先运行 [inspect_pptx_layout.py](scripts/inspect_pptx_layout.py) 自动读取页面尺寸、目标槽位的精确宽/高（cm）与比例、主题主色、字体及整页文本（用于去重与配色对齐）。
- **仅有页面截图或主题描述**：按目标区域实测比例或用途选择比例，简短说明假设，无需强制索取 PPT；只在技术关系或交付形式确实无法推断时提问。
- 严格遵循目标槽位比例，区分外部画布与可见主体范围，预留文字和连线留白，不可拉伸对象或裁掉关键结构、连线端点。

## 风格默认值与技术约束

用户要求和目标幻灯片风格优先。无指定时，采用克制的浅色学术配色：白底或柔和天空渐变底、浅灰结构、与页面一致的主题强调色（主线）、低饱和青蓝（辅助/大气）、深蓝（定位/终端输出）。避免无意义的霓虹、全息界面、戏剧化光照和装饰性细节。

必须保持技术对象、关系方向、因果和空间层次正确。编辑旧图时，不因美化而添加未经支持的传感器、通信链路或技术结论；看不清的标注不得当作已确认事实补写。

## 制作与交付

1. 明确核心信息、空间尺度、主次层级与目标比例；读取页面已有文字，制定“去重后”的极简标签清单与连线清单。
2. 优先收集/裁切真实实物照、权威公开科学图与作者论文核心图，搭建克制的矢量情景与连线框架；仅在确实需要局部插画时参考 [提示词模板](references/prompt-patterns.md) 调用图像生成工具。
3. 新建图默认保持标题、标签、公式、编号和关键连接线可编辑：提供**无文字纯净底图**与**可编辑组装版本**（支持 PNG + SVG 输出）。
4. **交付 `.pptx` 时实行双轨输出、绝不覆写原文件**：
   - `*_可编辑版.pptx`：原位替换为无文字底图 + PPT 原生可编辑形状、文本框与连接线（匹配原页字体与主色）；
   - `*_一体化图版.pptx`：原位替换为完整高清成品图，防止答辩电脑跨平台字体漂移。
5. **实际尺寸视觉验收**：将成品按实际槽位大小合成到目标页面预览图（或渲染 PPT 页面）中检查，逐项核对：无文字裁切、无相邻子图残影、无遮挡关键元素、缩小后字号清晰可读、主次与辅助关系一目了然。修复具体问题后再交付。

## 工具与可移植性

矢量情景框架、实物裁切抠图与合成优先使用 Python（Matplotlib / Pillow / `python-pptx`）或当前环境原生图形工具；栅格插画仅在兜底需要时调用图像生成工具。不绑定作者个人路径、账号或外部固定 skill。

若某项工具不可用，明确说明实际验证范围（例如未做 LibreOffice 离线转图时说明以像素预览验收），不宣称已完成未执行的检查。
